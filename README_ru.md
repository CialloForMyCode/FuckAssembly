<a id="what-is-fa"></a>

## Что такое Fuck Assembly

**Fuck Assembly**, сокращённо **FA**, — это проект набора языков программирования, который я начал после долгих мучений с ассемблером; в него входят [ONC](#what-is-onc) и [FUN](#what-is-fun).

Главная цель проекта FA — сократить использование традиционного ассемблера на уровне голого железа и дать более читаемый и более удобный для написания низкоуровневый язык с частью высокоуровневого синтаксиса.

| Язык | Парадигма | Что можно писать |
| :--- | :--- | :--- |
| **ONC** | Объектно-ориентированная (OOP) | Большая часть синтаксиса C# и многое из Java; проекты для x86_16 на голом железе |
| **fun** | Процедурная | Родной синтаксис fun для чистых программ на голом железе |

<a id="what-is-onc"></a>

## Что такое ONC

ONC — объектно-ориентированный (OOP) язык программирования, цель которого — принести синтаксис C# на более низкий уровень системы, без громоздкого рантайма .NET. Это значит, что по скорости компиляции, скорости работы и широте применения он может превзойти C#.

На нижнем уровне системы ONC не играет роль замены ассемблера — он пытается более современным синтаксисом пошатнуть господство C среди низкоуровневых языков высокого уровня.

> [!NOTE]
> Словом, ONC — не тот язык программирования, который стоит учить.

<a id="onc-comm"></a>

### Взаимодействие ONC

- ONC безболезненно использует **C# BCL**; обратное уже не работает — C# не может использовать **ONC BCL**. Синтаксис двух языков совместим лишь в одну сторону и лишь большей частью.
- Семантика ONC в некоторых случаях не совпадает с C#.
- ONC безболезненно взаимодействует с **fun**.

<a id="what-is-fun"></a>

## Что такое FUN

**fun** — процедурный язык программирования, цель которого — дать программисту возможность писать для голого железа вообще без ассемблера.

На голом железе fun заменяет ассемблер лучше, чем ONC: поддержка голого железа у fun выше, и у него нет громоздкого целевого рантайма ONC (Ts-UFO) — вместо него используется более компактный хостовый рантайм (Hs-UFO), а скомпилированный машинный код получается крайне лёгким.

<a id="fun-comm"></a>

### Взаимодействие fun

Поддержка у fun очень широкая, он умеет работать с:

- `ONC IL`
- `C LLVM IR`
- `Rust LLVM IR`
- `Zig LLVM IR`

> [!IMPORTANT]
> Важно: **сам fun не производит LLVM IR.**

<a id="what-is-ufo"></a>

## Что такое UFO

**UnFuckOverflow**, сокращённо **UFO**.

UFO — это не что-то конкретное, а концепция дизайна: она не опирается на традиционную структуру стека и кучи, а перестраивает её в структуру нового типа.

- Прежнюю структуру LIFO заменяет **выборка по указателю**.
- Данные в стеке и куче **выбрасываются сразу после использования**: взял один раз — старое значение тут же отбрасывается.
- Если продолжать класть в стек после достижения вершины, **выдавливаются самые нижние данные**, а не происходит переполнение стека.
- Выделенная в куче память **освобождается автоматически**; в большинстве случаев вручную освобождать ничего не нужно.

<a id="ts-ufo"></a>

### Ts-UFO

Целевой рантайм (Target-side UFO) компилируется в целевой файл вместе с машинным кодом.

<a id="hs-ufo"></a>

### Hs-UFO

Хостовый рантайм (Host-side UFO) определяет внутреннюю архитектуру программы на этапе компиляции; после того как она определена, структуру стека/кучи уже нельзя изменить во время выполнения.
